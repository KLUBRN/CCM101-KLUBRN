# Mission Reflection

**1. Which cloud infrastructure component do you think is the most important? Why?**
Networking, because cloud computing depends entirely on the internet — if either side of that connection is missing, nothing can communicate and the whole process breaks down.

**2. How does Linux support cloud computing?**
Linux is well-suited to cloud computing because it's lightweight and efficient, which makes it a natural fit for virtual machines with limited resources — something I noticed directly on my KillerCoda server. Working through the terminal also makes tasks easy to automate with scripts instead of clicking through menus. And because Linux works so well with tools like Git, I could document and push my findings to GitHub from the very same environment I used to investigate the server.

**3. Why is technical documentation important before deploying infrastructure?**
Documentation matters before deployment because it gives people something concrete to follow instead of leaving them to guess. In this lab, the checkpoint instructions and command lists were what let me know exactly what to do before creating, committing, and pushing anything. I also hit real errors along the way — `fatal: not a git repository`, `Author identity unknown`, and authentication failures on `git push` — and without documentation explaining what those messages actually meant, I wouldn't have known how to resolve them. That's the same reason it matters in real infrastructure work: documentation written ahead of time keeps a team working the same way, cuts down on avoidable mistakes, and makes it far easier to trace and fix problems once something does go wrong.

**4. What new skills did you learn during this laboratory activity?**
I learned how to build tables directly inside nano, and got a clearer understanding of how to create folders on GitHub by including the folder path in a new file's name.

**5. How has your GitHub portfolio improved after completing this mission?**
This time I was editing both directly on GitHub and through the CLI, which meant more commits were created compared to Lab 1.
